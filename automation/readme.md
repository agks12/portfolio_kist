# 연구 데이터 수집 업무 자동화

## 01. Overview

연구에 필요한 외부 기관 데이터를 정기적으로 수집하고 연구 시스템(OASIS)에 등록하는 반복 업무를 **Python + Playwright 기반 웹 자동화 프로그램으로 전환**한 프로젝트입니다.

기존에는 연구자가 관련 사이트에 직접 접속하여 데이터를 조회·다운로드하고, 필요한 형태로 정리한 후 연구 시스템에 다시 업로드해야 했습니다.

이를 자동화하여

> **외부 데이터 조회 → 파일 다운로드 → 데이터 정제/필터링 → 파일 생성 → 연구 시스템 업로드**

까지의 반복적인 업무를 프로그램이 수행하도록 구축했습니다.

데이터별 업데이트 주기가 서로 다른 점을 고려하여 자동화 프로그램을 각각 구성하고, Windows 및 Linux 환경의 스케줄러와 연계하여 **정해진 주기에 맞춰 자동으로 데이터가 갱신되도록 운영**했습니다.

---

## 02. Background

### Problem

연구 데이터 수집 업무는 정기적으로 반복되지만 다음과 같은 작업이 지속적으로 필요했습니다.

* 외부 데이터 제공 사이트 접속
* 계정 로그인
* 최신 데이터 확인
* 조건에 맞는 데이터 조회
* Excel 파일 다운로드
* 필요한 데이터만 추출 및 정제
* 연구 시스템(OASIS) 접속
* 업로드 대상 자료 선택
* Excel 파일 업로드

특히 데이터 업데이트 일정에 맞춰 사람이 직접 작업해야 했기 때문에 **휴가·부재 시 업무 인수인계가 필요하고, 주말이나 공휴일에는 데이터 갱신이 지연될 가능성**이 있었습니다.


## 03. Automation Architecture

두 종류의 연구 데이터를 각각 데이터 특성에 맞게 자동화했습니다.

```text
                    ┌────────────────────┐
                    │   Scheduler        │
                    │ Windows / Linux    │
                    └─────────┬──────────┘
                              │
                ┌─────────────┴─────────────┐
                │                           │
                ▼                           ▼
       ┌─────────────────┐        ┌─────────────────┐
       │ 자동화 프로그램 A │        │ 자동화 프로그램 B │
       │                  │        │                  │
       │ BANDTRASS       │        │ 가락시장 데이터   │
       │       ↓          │        │       ↓          │
       │ Excel 다운로드   │        │ 데이터 조회       │
       │       ↓          │        │       ↓          │
       │ 데이터 정제      │        │ Excel 다운로드   │
       └────────┬────────┘        │       ↓          │
                │                 │ 날짜 필터링       │
                │                 │       ↓          │
                │                 │ 파일 생성         │
                │                 └────────┬────────┘
                │                          │
                └─────────────┬────────────┘
                              ▼
                     ┌─────────────────┐
                     │      OASIS      │
                     │ 연구 데이터 등록 │
                     └─────────────────┘
```

각 자동화 프로그램은 데이터 제공 사이트의 구조와 업데이트 방식에 맞게 구현했으며, 최종적으로 연구 데이터 관리 시스템인 OASIS에 자동 등록되도록 구성했습니다.

## 05. Technical Implementation

### 5.1 데이터 다운로드 및 파일 처리

외부 기관에서 제공되는 데이터는 바로 업로드하지 않고, 각 데이터 특성에 맞는 후처리 과정을 거치도록 구성했습니다.

#### 데이터 유형 1

```text
외부 사이트
    ↓
최신 데이터 확인
    ↓
ZIP 다운로드
    ↓
압축 해제
    ↓
Excel 데이터 확인
    ↓
불필요 데이터 제거
    ↓
최종 Excel 생성
    ↓
OASIS 업로드
```

다운로드된 ZIP 파일은 자동으로 압축을 해제하고, Excel 데이터를 Pandas를 이용해 읽어 필요한 데이터만 정제하도록 구현했습니다.

예를 들어 특정 데이터의 경우 전자상거래 등으로 인해 일부 필드가 비어 있는 데이터가 발생할 수 있어, **업로드 전에 데이터 정제 과정을 추가하여 불필요한 행을 제거**했습니다.

---

### 5.2 데이터 기간 자동 처리

데이터 제공 사이트의 기준일을 기반으로 다운로드 대상 기간을 자동 계산하도록 구현했습니다.

전월 말일이나 월초와 같이 날짜 계산에 예외가 발생할 수 있는 경우를 고려하여 **월 변경 및 연도 변경 상황까지 처리**하도록 구성했습니다.

이를 통해 매번 사람이 날짜를 계산하여 입력하지 않아도 현재 데이터 기준으로 필요한 기간을 자동으로 산출할 수 있도록 했습니다.


---

### 5.3 보안 정보 분리

로그인 계정 및 파일 암호 등의 민감한 정보는 Python 코드에 직접 작성하지 않고 `.env` 형태의 환경설정 파일에서 관리하도록 구성했습니다.

```text
Python Script
     │
     ├── ID
     ├── Password
     └── File Password
             ▲
             │
          info.env
```

이를 통해 소스 코드에 계정 정보를 직접 노출하지 않고 실행 환경에서 필요한 인증 정보를 주입할 수 있도록 구성했습니다.

## 06. Problem Solving

### 6.1 사이트별 로그인 방식 차이 대응

데이터 제공 사이트마다 로그인 방식과 화면 구조가 달랐습니다.

특히 일부 사이트에서는 일반적인 비밀번호 입력 방식이 아닌 **가상 키보드 기반의 비밀번호 입력 방식**이 적용되어 있었습니다.

이에 따라 단순한 `fill()` 방식으로 해결할 수 없는 경우를 고려하여 화면의 가상 키보드 위치를 계산하고, 이미지 기반으로 키보드 영역을 인식한 후 마우스 좌표를 계산하여 입력하는 방식을 구현했습니다.

```text
가상 키보드 이미지
        ↓
화면 영역 좌표 계산
        ↓
OpenCV 이미지 매칭
        ↓
키보드 위치 파악
        ↓
키 좌표 계산
        ↓
Playwright Mouse Event
        ↓
비밀번호 입력
```

이를 통해 일반적인 입력 방식과 가상 키보드 방식이 혼재하는 환경에서도 자동 로그인이 가능하도록 대응했습니다.

---

### 6.2 실행 환경 차이 대응

자동화 프로그램을 Python 스크립트 상태로만 운영하지 않고 실행 환경에 맞게 배포할 수 있도록 `.exe`로 패키징했습니다.

또한 운영 환경에 따라 서로 다른 스케줄링 방식을 적용했습니다.

```text
Windows PC
   ↓
.exe
   ↓
Windows Scheduler
   ↓
자동 실행


Linux Server
   ↓
.exe
   ↓
Cron
   ↓
자동 실행
```

운영체제별 환경 제약을 고려하여 각각 적합한 실행 및 스케줄링 방식을 적용했습니다.

## 07. Automation Schedule

두 데이터는 서로 다른 업데이트 주기를 가지고 있어 각각의 특성에 맞게 자동 실행되도록 구성했습니다.

| 데이터      | 업데이트 주기 | 실행 방식 |
| -------- | ------- | ----- |
| 연구 데이터 A | 1일 주기   | 자동 실행 |
| 연구 데이터 B | 5일 주기   | 자동 실행 |

자동화 프로그램을 실행 파일로 패키징한 후 운영 환경의 스케줄러와 연계하여 **담당자가 매번 직접 실행하지 않아도 데이터 수집 및 등록 작업이 수행되도록 구성**했습니다.

## 08. Validation

자동화 과정에서 단순히 파일을 다운로드하는 것에 그치지 않고, 다음과 같은 단계별 검증을 수행하도록 구현했습니다.

### 수집 단계

* 최신 데이터 기준일 확인
* 다운로드 파일 존재 여부 확인
* 다운로드 완료 여부 확인
* 압축 파일 정상 처리 여부 확인

### 데이터 처리 단계

* Excel 컬럼 확인
* 날짜 데이터 변환
* 대상 기간 필터링
* 불필요 데이터 제거
* 최종 파일 생성 여부 확인

### 등록 단계

* OASIS 로그인
* 등록 대상 자료 선택
* 파일 업로드
* 업로드 프로세스 완료

이를 통해 **수집 → 가공 → 등록**의 전체 프로세스를 하나의 자동화 흐름으로 관리했습니다.

이에 따라 연구자가 필요할 때 최신 데이터에 접근할 수 있도록 지원하고, 반복적인 데이터 수집 업무에 소요되는 관리 부담을 줄였습니다.
